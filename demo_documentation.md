# Dynamic Population Density API – Demo Documentation

# Demo Documentation – Endpoints & Density Calculation
This document describes the available API endpoints and explains how population
density is computed.
It complements the setup guide and focuses only on API usage and behavior.


## Endpoints and density calculation
GET /density


Returns the population density for a given geographic location defined by
latitude and longitude coordinates.


The returned density value is expressed in people per square kilometer
(people/km²).


# Query Parameters
Parameter   Type    Required    Description
lat         float    Yes        Latitude in WGS84 (EPSG:4326), range [-90, 90]
lon         float    Yes        Longitude in WGS84 (EPSG:4326), range [-180, 180]


## Example Request
GET /density?lat=43.6045&lon=1.444


# full URL :
http://127.0.0.1:8000/density?lat=43.6045&lon=1.444


Example Response:
{
 "lat": 43.6045,
 "lon": 1.444,
 "density": 9719.2497253418
}


# Response Fields
Field      Type          Description
lat        float         Echo of the input latitude
lon        float         Echo of the input longitude
density    float         Population density in people/km²


## Density Calculation
Data Source
Dataset: Global Human Settlement Layer (GHSL) – GHS-POP R2023A
Projection: Mollweide (ESRI:54009)
Raster resolution: 100 m × 100 m


Calculation Process


1. Input coordinates
   -  The API receives latitude and longitude in WGS84 (EPSG:4326).


2. Coordinate Reference System (CRS) conversion
   - Coordinates are converted from WGS84 to the raster dataset CRS
      (Mollweide) using a coordinate transformer (This ensures correct alignment with the raster grid.)


3. Raster indexing
   - The transformed coordinates are mapped to a raster cell (row, column).


4. Raster sampling
   - A single pixel value is read from the population raster dataset.


5. Density conversion
   - Each raster pixel represents a 100 m × 100 m area.
   - Pixel area = 0.01 km²
   - Population density is computed as: density (people/km²) = population_in_pixel × 100


6. Response generation
   - The computed density is returned as a JSON response.




## more detailed from code
The raster lookup and density computation follow these key lines:


1) Transform WGS84 lat/lon → dataset CRS (x,y): x, y = self.transformer.to_dataset(lat, lon)
2) Convert (x,y) → raster pixel location (row,col) and read one pixel:


       row, col = self.dataset.index(x, y)
       window = Window(col, row, 1, 1)
       data = self.dataset.read(1, window=window)
       val = data[0, 0]




3) Convert to people/km² in the API endpoint:


density = service.get_density(lat, lon)
density_per_km2 = density * 100


Reason for × 100: each pixel represents 0.01 km², so converting to per-km²:
people/km² = people_in_pixel / 0.01 = people_in_pixel × 100


## Error and Edge-Case Handling


This section documents how the API behaves when the request is invalid or when
the density cannot be computed.


> Note: HTTP status codes are generated by FastAPI or raised by the application.




### 1 Invalid or Missing Query Parameters (HTTP 422)


If `lat` or `lon` is missing, or if either parameter is not a valid float, the
request is rejected automatically by FastAPI validation.


**Example request (invalid `lat`):**
GET /density?lat=abc&lon=1.0
http://127.0.0.1:8000/density?lat=abc&lon=1.0


**Status code:**
422 Unprocessable Entity


# Example response
```json
{
 "detail": [
   {
     "type": "float_parsing",
     "loc": ["query", "lat"],
     "msg": "Input should be a valid number, unable to parse string as a number",
     "input": "abc"
   }
 ]
}


2. Wrong Endpoint Path (HTTP 404)


If the URL path does not match an existing endpoint, the API returns 404.


Example request (wrong path format):
GET /densitylat=abc&lon=1.0


# Status code: 404 Not Found
Example response:


{
 "detail": "Not Found"
}


3.  Service Not Initialized (HTTP 503)


If the application service is not initialized (for example, if the raster
dataset failed to load at startup), the API returns 503.


Status code: 503 Service Unavailable


Example response:


{
 "detail": "Service not initialized"
}


4) Out-of-Bounds Coordinates / No-Data Cells (Returned Density = 0.0)


If the coordinate is outside the raster coverage, or if the raster cell contains
a no-data value, the service returns a density of 0.0 (people/km²) instead of
an HTTP error.
for example : http://127.0.0.1:8000/density?lat=90&lon=180
Example behavior:
Response status: 200 OK


Response body contains "density": 0.0
{
 "lat": 90,
 "lon": 180,
 "density": 0
}


This fallback ensures the API does not crash when the dataset does not provide
a valid value for the requested location.
